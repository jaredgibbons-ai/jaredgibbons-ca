## A. Fix first

### 1. Neighbourhood guide maps show a Google error  [GCP] then [CODE]
- Pages: /south-surrey-neighbourhoods.html, /langley-neighbourhood-guides.html (check every page using the same map component).
- Observed: popup "This page can't load Google Maps correctly. Do you own this website?" and "For development purposes only" watermark on a darkened map. Reproduced on three loads. The script loads from maps.googleapis.com with a key present.
- Fix: in Google Cloud, check billing is active on the project, Maps JavaScript API is enabled, and the key's HTTP referrer restriction allows jaredgibbons.ca/* and www. Open the browser console on the page to read the exact error name.
- Code follow-up: add a fallback so a failed map load shows the neighbourhood link list instead of a broken map.
- Done when: map renders with no popup or watermark on every guide hub.

### 2. Locked cards appear first in search results  [MRP]
- Pages: /recip.html, /map-search.html, /south-surrey-homes-for-sale.html (and other area pages using the same grid).
- Observed: the first two grid cards are blurred with "To access this listing, please create a free account" and a blue Signup / Login button. On desktop the embedded map sidebar opens with locked SOLD cards, because the map defaults to "Show both active and sold" sorted Price (low-high).
- Fix: default map to active listings only, sorted newest first. For the grids, hide login-only listings from logged-out visitors or sort them after public ones. Ask MRP support which of these are configurable.
- Done when: a logged-out visitor sees real, open listing cards first on all three pages at every width.

### 3. "Signup" links scattered through MLS listing details  [MRP]
- Page: any listing opened from the /recip.html grid (MRP reciprocity detail view).
- Observed: dozens of blue "Signup" links in the details table; the Room Information table is entirely "Signup" cells.
- Fix: hide gated fields for logged-out visitors and show one line instead: "Create a free account to see room sizes, price history and more." If MRP cannot do this, ask for an alternate detail template.
- Done when: no repeated Signup cells in the details table.

### 4. Results count typo  [MRP] or [CODE]
- Observed: "SHOWING: 1-121,249" on every grid. Should read "1–12 of 1,249". Likely a missing " of " separator, possibly hidden by site CSS applied to the embed.
- Done when: the count reads correctly.

### 5. Raw system message on Open Houses  [MRP] / [CODE]
- Page: /open-houses.html
- Observed: "We have found a total of 3,699 listings, but only 1,500 are available for public display. Please refine your criteria, to narrow the total number of matching listings." There is nothing on the page to refine by.
- Fix: narrow the default feed (for example this weekend, core areas) so the cap is not hit, or hide the message. City buttons already exist above it.
- Done when: the message no longer shows.
